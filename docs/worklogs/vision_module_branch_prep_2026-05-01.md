## 视觉模块接入边界

下一阶段不应直接大改阀门状态机。更稳妥的方式是先抽象阀门状态来源：

- `privileged`：当前 MuJoCo site/body/joint 直接读取，作为基准。
- `vision_debug`：使用 MuJoCo 图像或相机渲染，但允许与特权真值对比。
- `vision`：只使用视觉估计结果驱动控制。

控制侧理想输入保持一致：

- 阀门中心位置 `center`
- 阀门轴线 `axis`
- 预定抓点 `grasp_point`
- 阀门角度 `angle`
- 置信度或有效标志 `valid/confidence`

这样可以让视觉模块独立迭代，不破坏当前 IK、抓取和角度闭环控制链路。

## 初步实现建议

第一轮只做可观测性和接口准备：

1. 梳理当前 `SIM_STATUS_FILE` 中阀门相关字段。
2. 新增一个视觉状态中间文件或统一状态 adapter。
3. 用 MuJoCo 内置相机保存阀门区域图像，先离线做检测与真值对比。
4. 增加日志字段，记录视觉估计和 privileged 真值之间的位置、轴线和角度误差。
5. 只有在误差稳定后，再把控制输入从 privileged 切换到 vision。

## 风险点

- 视觉估计的阀门轴线和角度符号必须和现有 `valve_hinge` 定义一致，否则角度闭环会反向。
- 抓点估计误差会直接影响掌心贴合，几厘米误差就可能导致空夹或径向拉扯。
- MuJoCo 相机参数不等于实机相机标定结果，仿真视觉结果不能直接夸大为实机可用。
- 当前阀门转动 demo 仍含 soft connect 和 angle brake 工程近似，视觉模块不应掩盖这一事实。
